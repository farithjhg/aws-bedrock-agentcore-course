# SITE-README — AIP-C01 Docusaurus site

Operational notes for the Docusaurus v3 site that publishes the AIP-C01 exam-prep
course at `https://farithjhg.github.io/aws-bedrock-agentcore-course/aip_c01_examen/`.
The full design rationale lives in `SITE-PLAN.md`; this file records the chosen
mechanisms and the verification evidence.

## What this is

- A Docusaurus **v3**, **classic-preset**, **docs-only** site (no blog, no custom
  landing page). The course README is the home page at the subpath root (`slug: /`).
- Source project lives in `aip_c01_examen/site/`. The 15 course Markdown files are
  migrated into `aip_c01_examen/site/docs/` with frontmatter + rewritten links; study
  content is preserved verbatim.

## outDir mechanism (how built assets reach the subpath)

**Corrected approach (v2).** The original plan used `outDir: '../'` as a Docusaurus
config field. That is wrong on two counts: (1) `outDir` is a **CLI flag** in Docusaurus
v3, not a `docusaurus.config.ts` field — the build fails validation with
`These field(s) ("outDir",) are not recognized`; and (2) pointing the output at the
parent dir is unsafe because Docusaurus **cleans its output directory before building**,
which would delete the `site/` source mid-build.

The working mechanism:

1. `npm run build` (run in `aip_c01_examen/site/`) writes to the **default**
   `aip_c01_examen/site/build/`. `baseUrl: '/aws-bedrock-agentcore-course/aip_c01_examen/'`
   still prefixes every asset for the subpath.
2. The Pages workflow then, in a **"Stage built site" step**, removes the stale
   root-level files of the exam course (everything under `aip_c01_examen/` except `site/`)
   and copies `aip_c01_examen/site/build/.` into `aip_c01_examen/`.
3. `upload-pages-artifact` with `path: .` publishes the whole repo, so the compiled site
   now physically at `aip_c01_examen/` is served at the subpath. The AgentCore course at
   `intro_4h_agentcore/` is untouched.

The original course `.md` files that used to sit at `aip_c01_examen/` root (and the old
`index.html`) have been **removed from version control** — the single source of truth is
now `aip_c01_examen/site/docs/`. `node_modules`, `.docusaurus`, and `build/` are
gitignored.

## Ask this page chatbot

Every documentation page has an **Ask this page** button. The floating panel can
explain the current topic, connect it to exam discriminators and constraint
keywords, give a Northwind Support Assistant example, or ask an original practice
question. Answers stream from **Gemini 2.5 Flash** and are study aids, not an
authoritative source of AWS or exam facts.

### Visitor key and privacy

- There is no backend, shared key, repository secret, or key embedded in generated
  assets. Each visitor obtains their own key from
  [Google AI Studio](https://aistudio.google.com/apikey).
- The key is saved **only in this origin's browser `localStorage`**, not in a cookie,
  URL, server, or conversation log. It is sent directly to Google in the
  `x-goog-api-key` request header. Browser storage is not encrypted or isolated from
  other scripts on the same origin; avoid saving a key on a shared device.
- **Forget key** removes the saved key, clears the visible conversation and stops
  any pending answer. It does not revoke the key at Google; revoke it in AI Studio
  when necessary. Storage failures are displayed rather than silently ignored.
- Sending a question sends **the current page's indexed text, the documentation
  map, the question, recent conversation and selected related excerpts to Google**.
  The panel discloses this before sending. Do not enter sensitive information.
  Google's API terms, quotas and possible charges apply. Saving a key alone does
  not make a model request.
- Conversations live only in memory. Navigation to another document resets the
  visible history; navigation, closing, Clear, Forget key and unmounting cancel
  pending work. Stale tokens cannot update the new conversation.

### Indexing and grounding

The local [chat-index plugin](plugins/chat-index/index.ts) consumes the docs plugin's
resolved titles and permalinks, so frontmatter slugs and route prefixes are not
guessed from filenames. It strips frontmatter and uses the installed Docusaurus
heading transform for `##` / `###` section boundaries, including custom IDs,
duplicate-heading suffixes and the configured anchor case policy. Fenced-code
headings are not sections. Only public course fields enter the JSON.

`chat-index.json` is emitted for **both `npm run start` and `npm run build`**, and is
fetched lazily with `useBaseUrl` when the panel opens. CopyPlugin watches the generated
data file during development. A small global-data map identifies documentation
routes; non-doc routes do not show the widget.

The exact matching index entry is the primary context (up to 60,000 characters,
with an explicit omission marker if truncated). A local BM25-style keyword search
selects at most three sections from **other** pages: at most 2,400 body characters
per section and 6,000 characters including source labels overall. Related sources
retain their own title, route and heading ID. The documentation map helps direct
questions that the supplied material does not cover.

The request includes at most eight recent completed user/model messages, uses
temperature `0.3` and `maxOutputTokens: 2048`, and consumes `streamGenerateContent`
SSE with buffered UTF-8/newline parsing and `AbortController` cancellation.
Incomplete, blocked or failed answers are labelled and not reused as history.
Model Markdown is rendered with `react-markdown`; raw HTML and images are not
rendered. Internal links receive the deployment baseUrl, and unsafe URLs are
non-navigable. No model output is passed to `dangerouslySetInnerHTML`.

### Chatbot validation

From this directory:

```sh
npm test
npm run typecheck
npm run build
npm run test:built
```

Tests cover index metadata/anchors, retrieval budgets, split SSE chunks and
cancellation, safe Markdown/links, key storage, route changes and stale streams.
The built-output check compares **every indexed h2/h3 anchor with the generated
HTML** and verifies that routes exist under the deployment layout. Run it after
building, especially when upgrading Docusaurus because indexing reuses its heading
transform.

Local verification on 2026-10-27 (Node 24.11.0):

- `npm test`: **55 passed**; `npm run typecheck`: passed.
- `npm run build`: passed; `npm run test:built`: **2 passed**, covering all
  **15 documents, 115 sections and 100 h2/h3 anchors**.
- The development page and index returned HTTP 200; development JSON exactly
  matched the production index.
- Mocked browser checks passed for streamed Markdown, source links, page changes
  during streaming, Stop/Clear/Forget key, quota errors, key persistence and Escape.
  Both themes were checked at 1280x900, 390x844 and 320x568 without panel clipping or
  horizontal overflow. Only a synthetic key was used; real model requests were blocked.
- The build still reports the pre-existing `onBrokenMarkdownLinks` deprecation and
  the local-search theme's missing-blog-directory warning.

For a browser check, run `npm run start -- --no-open` and visit
`http://localhost:3000/aws-bedrock-agentcore-course/aip_c01_examen/`. Check both
themes, a narrow mobile viewport, navigation while streaming, Stop/Clear/Forget key,
and Escape. Mock the Gemini endpoint and use a synthetic key; automated tests do
not require or send real credentials.

## Offline search

`@easyops-cn/docusaurus-search-local` (`^0.51.1`) is included as a theme in both
`package.json` and `docusaurus.config.ts`. This package supports Docusaurus v2/v3. It
could not be installed/built locally (see "Local build gate" below), so **its clean
install is first confirmed by the CI build**. If CI fails on it, the fallback is to
remove the dependency and the `themes` entry and rebuild without search (the rest of the
site does not depend on it).

## trailingSlash

Set to `false` as the starting choice (explicit value avoids project-subpath refresh
ambiguity on static hosts). This should be **verified on GitHub Pages** by loading a deep
doc URL and refreshing it; if a deep link 404s on refresh, switch to `trailingSlash: true`
and rebuild. This could not be verified locally because no local build was run.

## Link rewriting

Every internal cross-link was rewritten to **root-absolute, extension-less** Docusaurus
doc links (`/`, `/blueprint/...`, `/tablas-decision/...`, `/practica/...`). Outbound links
to the sibling AgentCore course became absolute URLs:

- `../intro_4h_agentcore/README.md` →
  `https://farithjhg.github.io/aws-bedrock-agentcore-course/intro_4h_agentcore/README.md`
- `.py` source files →
  `https://github.com/farithjhg/aws-bedrock-agentcore-course/blob/main/intro_4h_agentcore/agent/<file>.py`

## CI (`.github/workflows/pages.yml`)

A build phase was inserted **before** `configure-pages` / `upload-pages-artifact`:

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: '20'
- name: Build AIP-C01 Docusaurus site
  working-directory: aip_c01_examen/site
  run: |
    npm install
    npm run build
```

`npm install` is used (not `npm ci`) because **no `package-lock.json` was committed** —
the lockfile could not be generated without a local install. Triggers (push to `main`,
`workflow_dispatch`), `permissions`, `concurrency`, `upload-pages-artifact path: '.'`, and
the deploy step are unchanged. The existing AgentCore (`intro_4h_agentcore/`) publishing
is untouched — those static files are uploaded as-is.

## .nojekyll

The repo-root `.nojekyll` is unchanged. A `static/.nojekyll` is also included so one lands
in the built output (`aip_c01_examen/.nojekyll`) regardless of the classic preset's own
emission.

## Local build gate — NOT RUN (environment constraint)

**Historical migration note:** the following records the original migration's
environment limitation, not the current chatbot validation procedure above.

**The authoritative `npm run build` with `onBrokenLinks: 'throw'` was NOT run locally.**
The workspace volume (`C:`) was full system-wide (~235 MB free), which is far below what a
Docusaurus `node_modules` install + build needs. Per the maintainer's decision, no local
`npm install` / `npm run build` / dev server was run; **GitHub Actions performs the real
build on push**. The first CI run is where any missed link or search-plugin issue will
surface.
